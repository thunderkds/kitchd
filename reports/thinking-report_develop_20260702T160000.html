Decision

Problem: How to break the full KitchenOS MVP (14 domain entities, RBAC, realtime, recurrence) into independently-gradable, dependency-ordered vertical slices that a solo-dev-run agent pipeline can execute one at a time.
22-task tracer-bullet breakdown, approved as-is, ordered Foundation → Guidelines/Inventory → Tasks/Notes → Communication → Dashboard/RBAC-audit/Polish/QA.
Each task cuts a full vertical slice (schema→API→UI where applicable) rather than a horizontal layer, so every completed task is independently demoable. Granularity was calibrated to the domain's real complexity: high-risk/high-blast-radius work (RBAC guard T002, stock deduction T011, RBAC audit T019) is isolated into its own task rather than bundled, so review effort concentrates where risk is highest. The user explicitly approved this granularity over both a coarser 15-task merge and a finer split, judging it the right balance for solo-dev execution.
